# SonnikToPower → экосистема «Гарнизон»: контракт данных

SonnikToPower отдаёт сводки своих тренировок другим офлайн-приложениям автора через `ContentProvider`. Доступ только на чтение. Облака и сети нет.

Константы контракта лежат в `app/src/main/java/com/sonnik/ecosystem/contract/EcosystemContract.kt`, пакет `com.sonnik.ecosystem.contract`. Файл ни от чего не зависит, его можно копировать в приложение-читатель как есть.

## Доступ

| | |
|---|---|
| Authority | `com.sonnik.topower.ecosystem` |
| Базовый URI | `content://com.sonnik.topower.ecosystem/` |
| Разрешение на чтение | `com.sonnik.ecosystem.permission.READ_DATA`, `protectionLevel="signature"` |
| Запись | не поддерживается: `insert`, `update`, `delete`, `bulkInsert` бросают `UnsupportedOperationException` |
| Текущая `schema_version` | `1` |

Как подключить приложение-читатель:

1. Объявить в манифесте то же разрешение с `android:protectionLevel="signature"` и запросить его:
   ```xml
   <permission
       android:name="com.sonnik.ecosystem.permission.READ_DATA"
       android:protectionLevel="signature" />
   <uses-permission android:name="com.sonnik.ecosystem.permission.READ_DATA" />
   ```
   Разрешение объявлено во всех приложениях экосистемы, поэтому порядок установки не важен. Обязательное условие: одинаковый ключ подписи. Если подписи разные, Android не даст установить второе приложение (`INSTALL_FAILED_DUPLICATE_PERMISSION`). Сборки, подписанные F-Droid своим ключом, с GitHub-сборками несовместимы.
2. На Android 11+ добавить в манифест видимость пакета:
   ```xml
   <queries>
       <package android:name="com.sonnik.topower" />
   </queries>
   ```
   Можно вместо этого указать `<provider android:authorities="com.sonnik.topower.ecosystem" />` внутри `<queries>`.
3. Если SonnikToPower не установлен, `query` вернёт `null`. Это нужно обрабатывать.

## Общие правила

- Даты и время в epoch millis (`Long`), веса и тоннаж в килограммах (`Double`). Мышцы — имена enum `Muscle`: `CHEST, FRONT_DELTS, SIDE_DELTS, REAR_DELTS, TRAPS, LATS, LOWER_BACK, BICEPS, TRICEPS, FOREARMS, ABS, OBLIQUES, GLUTES, QUADS, HAMSTRINGS, ADDUCTORS, CALVES`. Список может пополняться, неизвестные имена нужно пропускать.
- Период задаётся query-параметрами `from` и `to` в epoch millis, обе границы включительно. Если параметр не задан, берутся последние 7 дней: `from = now − 7 суток`, `to = now`. Нечисловое значение даёт `IllegalArgumentException`. Если `from > to`, курсор будет пустым.
- Тренировка попадает в период по времени начала (`started_at`).
- Разминочные подходы не учитываются нигде.
- Тоннаж подхода считается как в общей статистике приложения: рабочий вес × повторы × число снарядов. Рабочий вес — вес отягощения; для упражнений с собственным весом это вес тела + доп. вес. Пара гантелей или гирь считается за 2 снаряда, резина — по пиковому сопротивлению; у резины-помощи оно вычитается из веса тела. Подходы без веса или без повторов дают 0.
- `projection` поддерживается: передайте нужные колонки в любом порядке, неизвестная колонка даёт `IllegalArgumentException`. `null` возвращает все колонки. `selection` и `sortOrder` игнорируются, порядок строк описан у каждого URI.
- Неизвестный путь даёт `IllegalArgumentException`.
- В пустой базе исключений нет: курсоры пустые. Исключения — `info`, у которого всегда одна строка, и `recovery`, у которого одна строка на каждую мышцу в состоянии `NEVER`.
- Наружу не отдаются заметки, названия шаблонов и другие тексты пользователя. Единственное исключение — названия упражнений в `records`.

## Уведомления об изменениях

После любой записи в тренировки, подходы или упражнения SonnikToPower вызывает `contentResolver.notifyChange(content://com.sonnik.topower.ecosystem/)`. Записью считаются сохранение подхода, правка истории, удаление, импорт резервной копии. Подписка:

```kotlin
resolver.registerContentObserver(Uri.parse(EcosystemContract.BASE_URI), true, observer)
```

Курсоры провайдера тоже привязаны к этому URI (`setNotificationUri`). Уведомление приходит только пока процесс SonnikToPower жив. Если он был остановлен, данные за это время не менялись. Чтобы не пропустить изменение, сверяйте `info.last_changed_at` при старте.

## URI

### `content://com.sonnik.topower.ecosystem/info`

Одна строка.

| Колонка | Тип | Описание |
|---|---|---|
| `schema_version` | Int | версия контракта, сейчас `1` |
| `app_version` | String | версия SonnikToPower, например `1.25` |
| `last_changed_at` | Long | время последнего изменения данных тренировок, в том числе удаления; `0`, если изменений не было |

### `content://com.sonnik.topower.ecosystem/workouts?from=&to=`

Одна строка на тренировку, по возрастанию `started_at`.

| Колонка | Тип | Описание |
|---|---|---|
| `id` | String | UUID тренировки, постоянный |
| `started_at` | Long | начало |
| `finished_at` | Long? | завершение; `null` — тренировка ещё идёт |
| `duration_sec` | Long? | секунды: время с часов, если внесено, иначе `finished_at − started_at`; `null` у незавершённой тренировки без данных часов |
| `working_sets` | Int | рабочих подходов, без разминочных |
| `tonnage_kg` | Double | тоннаж рабочих подходов, кг |
| `body_weight_kg` | Double? | вес тела в начале тренировки; `null`, если не внесён |
| `avg_hr` | Int? | средний пульс, уд/мин; `null`, если не вносился |
| `max_hr` | Int? | максимальный пульс, уд/мин; `null`, если не вносился |
| `calories` | Int? | ккал; `null`, если не вносились |

### `content://com.sonnik.topower.ecosystem/muscle_volume?from=&to=`

Одна строка на каждую мышцу, у которой за период есть хотя бы один рабочий подход. Строки идут в порядке enum `Muscle`. Подход засчитывается каждой основной мышце упражнения, поэтому сумма по мышцам больше общего числа подходов. Упражнения без указанных мышц сюда не попадают.

| Колонка | Тип | Описание |
|---|---|---|
| `muscle` | String | имя `Muscle` |
| `working_sets` | Int | рабочих подходов на мышцу |
| `reps` | Int | сумма повторов в этих подходах; подходы без повторов дают 0 |
| `tonnage_kg` | Double | тоннаж этих подходов, кг |
| `workouts` | Int | в скольких тренировках мышца работала |

`working_sets` за период по умолчанию (7 дней) совпадает с недельным объёмом на схеме тела в приложении.

### `content://com.sonnik.topower.ecosystem/recovery`

Одна строка на каждую мышцу enum `Muscle`, в его порядке. Считается тем же расчётом, что схема восстановления в приложении (`computeMuscleStatus`), на момент запроса. Параметров нет.

| Колонка | Тип | Описание |
|---|---|---|
| `muscle` | String | имя `Muscle` |
| `state` | String | `RECOVERING` — ещё восстанавливается; `READY` — восстановилась; `STALE` — восстановилась, но не тренировалась больше 10 дней; `NEVER` — не тренировалась |
| `last_trained_at` | Long? | когда мышца последний раз работала: время завершения тренировки, а если её не завершили — начала; `null` для `NEVER` |
| `ready_at` | Long? | когда восстановится или восстановилась; `null` для `NEVER` |
| `recovered_fraction` | Double | доля восстановления от 0.0 (только что нагружена) до 1.0; `1.0` для `READY`, `STALE` и `NEVER` |

### `content://com.sonnik.topower.ecosystem/body_weight?from=&to=`

Вес тела, внесённый в начале тренировок, по возрастанию времени. Тренировки без веса пропускаются.

| Колонка | Тип | Описание |
|---|---|---|
| `measured_at` | Long | начало тренировки |
| `weight_kg` | Double | вес тела, кг |

### `content://com.sonnik.topower.ecosystem/records?since=`

Новые рекорды начиная с `since`, epoch millis; по умолчанию за последние 7 дней. Логика та же, что у рекордов в карточке «Поделиться результатами». По каждому упражнению берётся лучший рабочий подход с `since` и попадает в выдачу, только если он строго лучше всего, что было до `since`. Упражнения без истории до `since` не считаются: первый результат ещё не рекорд. Одна строка на упражнение, по возрастанию `achieved_at`. Если сменить `since`, набор рекордов может измениться: он сравнивается с историей до этой даты.

| Колонка | Тип | Описание |
|---|---|---|
| `exercise_id` | String | UUID упражнения, постоянный |
| `exercise_name` | String | название упражнения, как его видит пользователь |
| `metric` | String | метрика сравнения: `E1RM` для упражнений с весом и повторами, иначе первая измеряемая: `WEIGHT`, `REPS`, `TIME`, `DISTANCE` |
| `value` | Double | значение: `E1RM` и `WEIGHT` — кг, `REPS` — повторы, `TIME` — секунды, `DISTANCE` — км |
| `achieved_at` | Long | начало тренировки с рекордом |

`E1RM` — расчётный разовый максимум по формуле Эпли: вес × (1 + повторы / 30), при 1 повторе равен весу.

## Версионирование

- Добавить колонку или URI можно без смены `schema_version`. Читатели должны искать колонки по имени (`getColumnIndexOrThrow`), а не по позиции, и не падать на незнакомых колонках.
- Удалить или переименовать колонку или URI, а также изменить смысл или единицы значения можно только с увеличением `schema_version`. Старый вариант при этом сохраняется ещё одну версию.
- Имена authority, разрешения, путей и колонок меняются только по согласованию: по ним читает «Крепость» (`com.sonnik.garnizon`).
- Приложение-читатель сверяет `info.schema_version` с версией, которую знает. Если версия больше, можно читать известные колонки. Если меньше, некоторых колонок может не быть.
